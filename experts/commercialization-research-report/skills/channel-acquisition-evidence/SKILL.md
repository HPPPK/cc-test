# 多源渠道获客证据包

## 目标

为报告第 5.5 节和渠道优先级建议提供真实、可复核的输入：不仅列关键词，还要说明哪些渠道页面、内容、讨论、分发或投放材料实际支持该判断，以及哪些结论目前不能支持。

本 Skill 不预设产品、行业、国家、竞品、平台或渠道。根据本轮产品方向、用户任务、市场范围、已打开页面和用户材料动态选择来源；来源的“广泛”看独立来源类型和实际内容，不看链接数量。

## 工具与边界

- 只用当前会话真实可用的工具。公开页面必须由 `Playwright` 实际打开；只有研究方向缺少 URL 时，可用它的 显式搜索动作 做一次可观察的公开搜索动作序列发现真实链接，再打开具体页面。本 Skill 不授予 Playwright 以外的额外搜索、登录、验证码绕过、批量抓取、付费数据或写文件能力。
- 不能把候选 URL、页面标题、搜索摘要、模型记忆、竞品官网、单个内容页或单一平台热度升级成 SERP 排名、广告投放、用户规模、付费意愿或转化率。
- 页面受限、验证码、403/429、robots、地区限制、登录墙或无关结果都属于有效调研结果：记录限制并继续从其他适用来源类别补充，不要报错或停止报告。

## 研究步骤

### 1. 先构造关键词与验证问题

优先形成 4–6 个有区分度的关键词方向；材料不足时可更少。可按实际产品选择品牌、品类、任务/痛点、替代方案和使用场景，不要求每类都有。

对每个方向写：

`关键词方向 | 希望验证什么 | 具体平台/站内入口 | 发现后必开的页面类型 | 可见指标或原始观察 | 目标字段 | 失败后的下一路线 | 当前状态`

### 2. 形成多源候选计划

按本轮真实可获得性选择并尝试以下独立来源类别，而不是机械要求所有类别：

1. **搜索结果或投放快照**：实际可打开的搜索结果页、用户提供 SERP/广告位截图、内部投放后台或合规公开广告资料。
2. **产品与分发页面**：官网、价格页、应用商店、下载站、插件市场、官方文档、官方 GitHub 或更新日志；无论属于本品、竞品还是替代品，均是第一方产品事实，用于产品事实和分发入口，不单独证明需求或来源广泛。
3. **外部内容与社媒**：独立作者、媒体、创作者或用户发布的已打开文章、视频、笔记、公开评论；用于内容供给、品类教育和场景表达线索。单条内容页只说明该页面存在，不能单独证明渠道获客有效、内容规模、用户需求或付费意愿。
4. **公开讨论与评价**：已打开的问答、论坛、评价、功能请求、迁移或替代方案讨论；用于任务、痛点和替代方案信号。
5. **行业、趋势或用户材料**：公开行业资料、权威数据、用户访谈、问卷、客服、投放或内部行为材料；按其原始定义使用。

搜索页、话题页、分类页和平台根页仅用于发现候选链接。若最终引用帖子、视频、评价或文章，必须再打开具体内容页。

### 2a. 具体平台与页面路线

- **中文渠道候选**：按产品适配性选择百度/Bing/360 的实际 SERP、知乎公开回答、B站具体视频页、小红书公开笔记、微信公众号公开文章、微博公开帖、少数派/V2EX/CSDN 文章或讨论页、以及 Microsoft Store/Apple App Store/各适配扩展商店的具体分发或评价页。
- **海外渠道候选**：按市场与产品适配性选择 Google/Bing 实际 SERP、YouTube 具体视频页、Reddit/X/Product Hunt/Hacker News/LinkedIn 具体页、独立媒体或教程页、以及适配的 Apple/Google/Microsoft/Chrome/Edge 商店页。
- 不需要把清单所有站点都访问一遍；每个候选渠道必须明确“平台 → 具体页面 → 可观察字段 → 不能外推范围”。页面受限、无关或无结果时，改走相同渠道字段的下一具体路线；不要用一个 SERP、平台根页或竞品官网替代具体内容/分发/评价页。

### 2b. 适用时的网站 SEO 快速审计

仅当本轮产品或直接竞品存在**公开可访问的官网 / 产品页 / 落地页**，且自然搜索是合理的获客候选时才执行。本步骤由渠道研究负责，是对商业分析的补充；没有独立站、SEO 当前不适用、页面受限或材料不足时，如实记录并继续，不向用户索要“SEO 方向确认”，也不阻断报告。

对已实际打开的官网或落地页，只做可追溯的**样本级**观察：

1. 打开首页与一个最相关的产品、功能、价格或转化落地页；记录 URL、页面角色、标题、可见主标题、描述 / canonical / robots / sitemap / 结构化数据等页面内或公开文件中**实际可见**的项目。
2. robots.txt、sitemap 或结构化数据只在已实际打开对应 URL、页面源码或公开链接时记录；“未取得”不等于“缺少”。单条失效链接只有在其 URL 实际打开并失败后才能记录。
3. 只要当前工具没有可复现的速度、移动端、全站抓取或统计测量，就不要填写 Core Web Vitals、首屏秒数、移动友好、死链总数、Meta 重复比例、图片 ALT 比例或全站 SEO 健康分。
4. 一页或少量样本页只能支持“该样本页观察到什么”，不能推导整个网站。**不得生成 SEO 总分、站点级百分比、全站问题数量，或把找不到 sitemap / Schema 写成已确认缺失。**

### 2c. 关键词意图与内容机会

在产品任务、竞品页和实际 SERP / 内容页基础上，形成 3–6 个有区分度的关键词或主题方向；材料不足时可更少。每个方向写清：

`主题 / 关键词方向 | 用户任务与意图 | 已打开 SERP、竞品页或内容页 | 当前供给或差异线索 | 可测试内容角度 | 证据状态与不能外推范围`

- 不从模型记忆补月搜索量、CPC、自然排名、流量或转化率；除非本轮实际打开的公开来源能支持相应数字。
- 内容计划是优先级建议，不要求强行凑“每周几篇”或“一个月固定篇数”。优先写清先测试什么内容角度、服务哪个任务、为什么、用什么页面或行为信号决定继续/调整。
- 网站 SEO 样本、关键词意图与内容建议均要回到具体 URL；它们可以作为渠道建议的依据，但不能替代用户需求、市场规模或付费意愿证据。

### 3. 逐页建立研究回执

每个实际使用的页面都记录：

`具体平台 | 候选入口/发现方式 | 已打开 URL | 页面类型 | 访问日期 | 可见指标或原始观察 | 支持什么 | 不能支持什么 | 状态（已打开/受限/无关/无结果） | 下一路线`

- 只有具备 `已打开 URL + 访问日期 + 实际观察` 的回执，才可使用“本次采集”“已观察”“可见广告位”“排名”“首页”“占据”“未观察到”“未发现”“不存在”等事实态措辞；“未观察到 / 未发现 / 不存在”同样属于负向观察结论，不是可随意使用的证据缺口标签。
- 只有 URL 但未打开时，只能称“候选链接”或“公开页面线索”；未取得对应查询回执时只能写“未取得 / 无法确认”，不能写成未观察到或不存在。
- 只有一个来源类型时，明确写“来源集中”；不要把同一官网、同一平台或多个同类页面算作多源。

### 4. 输出渠道证据包

交给主代理和独立复核子代理的输出必须包含：

1. **关键词地图**：关键词方向、目标用户任务、预期意图、当前证据状态；适用时附上关键词主题簇和可测试内容角度。
2. **网站 SEO 样本观察（适用时）**：实际打开的官网 / 落地页、观察到的页面内或公开技术项、可支持与不可支持的范围；未执行或受限时如实说明。
3. **来源覆盖摘要**：本轮实际尝试/成功/受限的来源类别；哪些类别是独立外部信号，哪些只是第一方事实。
4. **研究回执台账**：逐条列出实际 URL、日期、观察、限制与证据边界。
5. **5.5 写作映射**：每个表格单元格或渠道建议使用哪些来源编号，并写清具体平台/页面；应标“已观察、公开页面线索、推断、待验证”中的哪一种。不得把“内容平台”“海外社区”“搜索发现入口”写进平台/渠道列。
6. **渠道优先级候选**：核心、辅助、探索渠道各自的依据、适用条件、风险和下一步最低成本验证动作。

## 写入 5.5 的规则

- 先写采集说明，诚实列出本轮取得与缺失的材料；没有真实 SERP/广告位时写“未取得完整 SERP 快照 / SEM 未公开确认”，但继续完成关键词地图与渠道建议。
- SEO 列优先写实际占位来源、关键词意图或已打开网站样本观察，并在信息来源表保留 URL 和日期；没有完整 SERP 时不得写“排名第一”“全面占位”。网站样本只写页面级事实与明确边界，不写无抓取依据的 SEO 总分、百分比或全站诊断。
- SEM 列只写真实广告位、用户截图或可复核投放材料；不能用推测的 CPC、广告主数、预算或泛行业常识补全。
- “竞争强度”可以是工作判断，但要标“已观察”或“推断”，说明其来源边界。
- 渠道建议至少区分核心、辅助或探索中的适用层级；每项说明基于何种证据状态、适用条件和验证动作。单条外部内容或只有第一方产品页面时，默认只能作为“探索/待验证”或内容供给线索；只有多个独立信号或真实渠道表现材料才可作为核心渠道的依据。没有预算数据时不编预算比例。

## 完成检查

在返回前自查：

- 是否存在把未打开 URL、单一平台内容、竞品功能页或搜索摘要说成已观察事实？
- 是否把少量官网页面样本写成全站 SEO 分数、百分比、死链总数或已确认缺失？
- 是否把内容供给当成用户需求、市场规模或付费意愿？
- 是否把多条同一官网/同一平台链接当成来源广泛？
- 是否保留了访问受限和无结果，而不是静默用别的来源替代？
- 是否让主代理能在不编造的前提下继续写出完整、可执行的 5.5？

## 平台状态与报告范围一致性

维护的开放平台入口由 A/B/C 分账后逐项做一次有界发现尝试，不设成功率、深读或引用数量门槛；来源库外的渠道、内容平台和社区仍按产品适配性自由拓展。每个实际使用的平台应自然保留“具体页已打开 / 访问受限或无结果 / 仅候选链接 / 后续分发建议”之一。仅见超链接、搜索摘要或官方转述时，不能写成该平台内容、评论或渠道表现已经核验。

最终 REPORT_SCOPE 与渠道章节只能把有本轮具体 URL 且实际被报告使用的平台称为已覆盖或已调研；未被报告实际使用的成功访问仍完整保留在 06，不能自动升级成正文事实来源。访问受限、未打开候选及未来上线或分发动作必须清楚标为限制、候选或后续建议。该一致性要求不会阻断有证据缺口的报告。
