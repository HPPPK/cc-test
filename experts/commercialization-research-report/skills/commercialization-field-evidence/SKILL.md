# 商业化报告字段证据颗粒度

## 目的

把已打开的网页和用户材料写成可用于决策的具体报告内容，而不是把它们压缩成“社区有讨论”“用户待验证”一类来源类别。这里的示例只说明颗粒度和边界，不携带任何产品、平台、数字或人群事实。

## 研究路线先于结论

在已有材料交接中简要说明已知事实、关键缺口、下一条线索，不新增表格或必填格式。沿搜索返回的真实链接或用户/官方入口跟进；链接不透明时直接打开原链接或点击原结果，不猜帖子编号。打开后先核对标题和正文是否回应任务，不匹配就改查。已查清的事实复用，余量优先用于会改变建议的缺口，不凑品牌数或扫完目录。

在 `01-research-brief.md` 中为每个关键商业字段写一条路线：

`字段 / 候选人群或任务 / 要找的证据 / 中国公开来源候选 / 海外公开来源候选 / 查询词或站内入口 / 具体页面发现后要提取的字段 / 失败后的下一条路线`。

市场范围未明确时，不默认某个市场；但完整公开调研可分别探索适用的中文与海外公开来源，并把它们的证据状态分开写。平台根页和话题页不是用户正文；真实相关 SERP 摘要可作为有限线索进入报告，归属实际搜索页并注明目标原文未核验。具体帖子、视频、文章、评价、应用商店或数据页按实际取得内容使用，不把摘要移到目标网址下冒充原文。

## 具体来源而非泛来源类别

07 用普通 Markdown 保留“引用编号→精确来源”，例如 `- [S10]: audit:english-query` 与 `- [S15]: audit:product-query`，示例 ID 不是实际证据。即使同属 Google，查询不同仍是不同页面；正文、来源摘要、URL 必须对应同一页。F 补回材料时给出该页真实编号或 audit 身份，主代理新增/使用正确引用，不把内容塞进另一条查询的旧编号，也不按域名合并。编号可不连续，无需重排全表。

摘要缺字不等于未取得：审计表是导航摘要，先核对 06 下方原文摘录和已声明研究分片；截断标记说明只是部分原文。验证后真实返回正文与历史受限记录分别保留，不能用旧状态把成功材料清零。引文副本只因换行排版不同不要求重写；若与原始来源仍有疑点，D 核对并限定主张，不靠循环 Edit 或补造原文消除告警。

- **正确**：`知乎｜某公开回答｜作者描述在……任务中……；页面日期……；仅支持这一类任务线索。[n]`
- **错误**：`中文社区｜用户有需求。`
- **正确**：`Bing 单次 SERP｜查询词……｜当次可见候选……；不代表搜索量、稳定排名或需求规模。[n]`
- **错误**：`搜索发现入口｜热度较高。`

如果一个具体页面受限，只记录该页面受限，然后继续相同字段的下一条平台或页面路线；竞品官网不能冒充用户反馈；真实相关摘要可保留为任务线索并注明原文未核验，其他人群的内容说明边界。

## 母版字段的短示例

- **1.1 产品定义**：`面向……角色在……任务中，通过……入口完成……；“……”仍是待验证交互假设。`
- **1.2 功能行**：`能力｜用户当前卡在……｜完成后可观察到……｜必备 / 加分。`
- **1.3 产品形态**：`形态：……；核心链路：……；典型任务：……；现有替代：……；频次证据：已取得 / 待验证；首发边界：……。`
- **2.2 论据行**：`具体来源或产品输入显示……；它支持……，但不支持……；因此当前只建议……。`
- **2.3 机会窗口**：`已观察到……；因此可测试……；成立条件是……；若……则推翻。`
- **2.4 平台热度行**：`具体平台或页面｜可见指标或讨论主题｜数字或原始观察 + [n]｜只能得出的有限判断｜页面日期与采集日。` 不能把“社区”“内容”“搜索入口”当成平台名。
- **3.1 用户画像行**：`角色 + 触发任务｜当前替代、为什么不足、候选价值｜具体用户材料或清楚标出的推演、来源与边界。`
- **3.2 痛点段**：`谁在什么情境下做什么；现有做法；实际阻力或原始表达；产品含义；该页不能外推什么。`
- **4.1 / 4.2 变现与定价**：`竞品的具体收费或免费边界是事实；新品模式、价格或升级阈值只能写成（AI推断）测试方案，并说明验证方法。`
- **5.1–5.3 竞品**：`按竞争范式列出实际可比产品；每个产品只写本轮已取到的功能、价格、分发或留存字段，缺失字段不要拿别的产品补。`
- **5.5 搜索获客**：`一个关键词 + 一个实际 SERP 或落地页 + 能观察到的页面类型；搜索摘要、AI 概览和广告模块不得伪装为自然排名。`
- **6.1 决策闸门**：`具体假设｜为什么与本轮证据相关｜最小验证动作｜什么结果会改变继续或停止决定。`

## 从章节职责到完整分析示例

以下示例是假设材料，只演示分析过程，不是本轮事实、真实报价或默认产品方案；不得抄成来源或结论。

### 产品方案：从事实到取舍

假设材料：甲工具有复杂自动化，乙工具提供基础快捷入口；一条具体用户反馈说初始配置费时。这只能说明可比方案与一个任务阻力，不能证明普通用户普遍需要新工具。

可用于 1.2 / 1.3 / 5.4 的完整分析：**候选首发方案（AI推断）**是预置少量可修改的任务动作、执行前预览和失败撤销，而非复制完整自动化平台。**依据**是现有工具已覆盖复杂能力，该反馈指向配置成本；**替代与取舍**是继续使用免费工具或手动配置，新方案减少初配步骤但牺牲灵活性，也会增加模板维护。**验证**是用同一任务比较首次完成、出错与再次使用选择；若预设不能减少操作或用户仍选原工具，就调整方向。这是建议，不是已实现功能或已证实偏好。

### 商业建议：价格未知也要比较选项

假设材料：具体页面确认某产品免费入口与付费导出存在；用户任务呈现单次处理，但未取得支付行为。4.1 / 4.2 可以建议先比较“免费预览后按次导出”和订阅：前者承诺低，可能适合偶发任务；后者需要重复价值，不能仅因竞品有订阅便推荐。说明免费替代、算力/维护成本尚缺什么，以及什么观察会改变推荐。若有已核验的价格锚点与可比范围，可提出明确标为假设的测试价；没有锚点或成本依据时，不编造金额，也不把整章缩成“价格未知”。

### 渠道：公开路径可以支持有边界的建议

假设材料：一个教程页展示任务结果，CTA 进入试用页。5.5 可以提出“任务词教程 → 同任务示例 → 试用入口”的候选路径，解释内容与任务如何匹配、用户可能在哪一步流失、先记录哪些动作。无需先证明获客有效；单页不证明排名、搜索量或转化。若试用入口不承接教程中的任务，应先修承接而非扩大投放。

## 各角色如何使用现有指南

- A/B/C 围绕分配字段选择决策相关材料：A 比较替代、能力与收费边界；B 保留具体任务、现有做法、阻力与反例；C 解释公开入口、承接动作、商业选项与适用条件。在剩余预算内优先补会改变建议的缺口，不按来源数量凑配额。
- D 把来源真实性与方案合理性分开检查：无来源的事实须降级；有依据且标为推演的产品方案、测试价和渠道建议，不因未有支付/效果验证就整体删掉。
- E 保留不同章节的新增信息：依据、建议、替代、取舍与可推翻条件。共通限制集中说明，各章只留影响本章判断的条件；同一案例可用于不同决策，但不复制故事与免责。价格或获客效果未知时，仍用已取得的机制提出有依据的条件性方案，不把整章压成“尚未证明”。这不是必填格式，材料不足如实说明，不靠加字制造深度。
- 主代理把这些具体内容填入相应字段。F 对照 07 与 HTML，检查是否漏掉已有的重要建议、差异、收费条件、渠道机制及来源；已存在但丢失的内容做最小补丁，不追加浏览、代理或复核轮次。核对正文引用编号与 SOURCE_ROWS 一一对应；受限页不能列为事实来源时，去掉相关句子的悬空编号并保留真实访问限制，不给它伪造来源行。没有重要遗漏就结束，不为润色卡住交付。

## 交付前自检

每一项“用户、痛点、内容平台、热度、渠道或竞争结论”都应回答：哪个具体页面、谁或什么、发生在什么任务、页面何时、它能说明什么、不能说明什么。若答不上来，改为证据缺口或有依据的推演，不要用泛称填表。


## 材料与最终引用同步

整理 07 时，推荐使用普通 Markdown 来源编号，例如材料段落保留 [S1]，文末写 [S1]: https://真实已审计的具体页面；主代理写入对应报告字段时沿用这个编号。一个编号只对应一个页面，同一页面可以支撑多个有明确边界的细节。这不是新的格式门槛：完整 URL 写法继续可用，不要求新增 JSON、文件或固定版式。

只把正文实际采用的已审计页面关联到来源表；候选或仅访问过的入口继续在 06 保留。来源编号、实际 URL、来源名称要相互一致，不能把视频编号代替视频 URL，不能把 Gitee 描述配到 GitHub 链接。合并重复具体页面来源行时保留全部引用编号和不同支撑内容。同一搜索 URL 的不同审计记录不能合并；已有明确审计 ID 的来源保留其绑定，07 的 URL 编号不能覆盖该次访问。

不要复制上游明显影响理解的错字或坏句，也不要把各章不同的产品机制、用户任务、竞品限制、渠道条件压成同一句结论；先按上下文和已有材料修正。纯写作风格不同不是重新调研或阻止交付的理由。


## 长材料读取与来源身份

主代理、吸收与复核均按累计读取完整文件处理 07/08：长文件分页至 EOF，小文件也可整读，不以一次 Read 的参数形式判定完成。读取失败或材料已改写时，不复用旧版本读取记录。

长文章、视频和搜索 URL 不要凭标题或平台名重新拼接，也不要删除参数。07 可保留 [S1]: audit:<exact-audit-id>，与事实旁的 [S1] 配套；主代理沿用，服务端按同一次真实成功审计恢复完整页面 URL。没有审计 ID 时复制完整已审计 URL。一个编号对应一个页面/访问记录，多页面用多个编号；缺少这种可选编号不阻止交付，不新增 JSON 或字段配额。

未取得、不得冒充、未来建议不等于已观察事实；空补写清单和可选建议不构成必须补丁。只有具体的来源支持错误或遗漏才要求修正。


## 收尾整理：复用复核结果，不把未采用写成未取得

E 先完整读取 brief 与 05，再按需回查 06 或已登记分片的具体段落；D 已完成全分片复核，不要求 E 再整读所有原始材料。先保存实质章节材料与来源；只用 Read/Write，Write 覆盖保存时带齐累计正文，不把空提纲或压缩摘要当成已完成。

区分“已取得并采用、已取得但未采用、部分取得、未取得、访问受限”：未列入来源表不等于未取得。视频简介可读而评论未取得，是部分证据，不是整个平台受限。按具体页面和本次访问核对，不得用另一条失败记录覆盖成功内容。

每个实际使用的资料保留实际取得页的完整 URL 或真实 audit ID；摘要引用搜索页，不要求取得原文，推荐一页一编号并在正文与来源表沿用；多条评论、博文不得只留一个代表链接，搜索结果不得换成网站首页。普通 Markdown 引用定义、行内链接与带明确编号的来源表都可用，不新增格式或来源数量门槛。

公开标价或免费边界只能证明竞品采用了该方案，不能证明转化、盈利或付费意愿已经验证；一家竞品免费商用不能证明整个品类无法靠商用授权收费。有依据的 AI 推断继续保留，但要写依据、成立条件与可推翻条件，不能伪装为已验证定论。

08 在现有复核中检查上述三点，只提出已有证据支持的最小章节/来源补丁，不新增调研、代理、复核轮次或生成门槛。

## 07→HTML 决策细节保真

07 不只是提纲：按现有章节保留已复核的重要证据簇、互相矛盾的观察、用户任务与当前替代、竞品计费单位与免费边界、具体渠道机制、推断依据及证伪条件。主代理填字段时逐簇核对，不能只带结论和来源而丢失支撑细节；F 只对已有来源支持的遗漏定位 07 段落与母版字段，做一次最小补丁。视频只读简介时不得声称看过演示，零散帖子不能代表总体需求；不能靠加字、加页、加空表或来源配额制造深度。

### 最终决策的具体程度

每章用已有证据说明具体候选方案、当前替代、取舍与推翻条件；未知市场规模不阻止提出有依据且标为假设的产品方案。保留用户原任务、免费层关键额度和不同路径，不把它们全部压成“待验证”。审计与工具最终返回冲突时交主代理核对精确记录，保留争议原文，暂不采用争议结论，不删除其它已支持细节或重启调研。
