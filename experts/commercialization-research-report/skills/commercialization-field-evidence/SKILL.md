# 商业化报告字段证据颗粒度

## 目的

把已打开的网页和用户材料写成可用于决策的具体报告内容，而不是把它们压缩成“社区有讨论”“用户待验证”一类来源类别。这里的示例只说明颗粒度和边界，不携带任何产品、平台、数字或人群事实。

## 研究路线先于结论

在 `01-research-brief.md` 中为每个关键商业字段写一条路线：

`字段 / 候选人群或任务 / 要找的证据 / 中国公开来源候选 / 海外公开来源候选 / 查询词或站内入口 / 具体页面发现后要提取的字段 / 失败后的下一条路线`。

市场范围未明确时，不默认某个市场；但完整公开调研可分别探索适用的中文与海外公开来源，并把它们的证据状态分开写。平台根页、话题页和 SERP 只用于发现；报告使用的内容必须来自实际打开的具体帖子、视频、文章、评价、应用商店或数据页。

## 具体来源而非泛来源类别

- **正确**：`知乎｜某公开回答｜作者描述在……任务中……；页面日期……；仅支持这一类任务线索。[n]`
- **错误**：`中文社区｜用户有需求。`
- **正确**：`Bing 单次 SERP｜查询词……｜当次可见候选……；不代表搜索量、稳定排名或需求规模。[n]`
- **错误**：`搜索发现入口｜热度较高。`

如果一个具体页面受限，只记录该页面受限，然后继续相同字段的下一条平台或页面路线；不能用竞品官网、搜索摘要或另一个人群的内容代替用户材料。

## 母版字段的短示例

- **1.1 产品定义**：`面向……角色在……任务中，通过……入口完成……；“……”仍是待验证交互假设。`
- **1.2 功能行**：`能力｜用户当前卡在……｜完成后可观察到……｜必备 / 加分。`
- **1.3 产品形态**：`形态：……；核心链路：……；典型任务：……；现有替代：……；频次证据：已取得 / 待验证；首发边界：……。`
- **2.2 论据行**：`具体来源或产品输入显示……；它支持……，但不支持……；因此当前只建议……。`
- **2.3 机会窗口**：`已观察到……；因此可测试……；成立条件是……；若……则推翻。`
- **2.4 平台热度行**：`具体平台或页面｜可见指标或讨论主题｜数字或原始观察 + [n]｜只能得出的有限判断｜页面日期与采集日。` 不能把“社区”“内容”“搜索入口”当成平台名。
- **3.1 用户画像行**：`角色 + 触发任务｜当前替代、为什么不足、候选价值｜具体用户材料或清楚标出的推演、来源与边界。`
- **3.2 痛点段**：`谁在什么情境下做什么；现有做法；实际阻力或原始表达；产品含义；该页不能外推什么。`
- **4.1 / 4.2 变现与定价**：`竞品的具体收费或免费边界是事实；新品模式、价格或升级阈值只能写成（AI推断）测试方案，并说明验证方法。`
- **5.1–5.3 竞品**：`按竞争范式列出实际可比产品；每个产品只写本轮已取到的功能、价格、分发或留存字段，缺失字段不要拿别的产品补。`
- **5.5 搜索获客**：`一个关键词 + 一个实际 SERP 或落地页 + 能观察到的页面类型；搜索摘要、AI 概览和广告模块不得伪装为自然排名。`
- **6.1 决策闸门**：`具体假设｜为什么与本轮证据相关｜最小验证动作｜什么结果会改变继续或停止决定。`

## 交付前自检

每一项“用户、痛点、内容平台、热度、渠道或竞争结论”都应回答：哪个具体页面、谁或什么、发生在什么任务、页面何时、它能说明什么、不能说明什么。若答不上来，改为证据缺口或有依据的推演，不要用泛称填表。


## 材料与最终引用同步

整理 07 时，推荐使用普通 Markdown 来源编号，例如材料段落保留 [S1]，文末写 [S1]: https://真实已审计的具体页面；主代理写入对应报告字段时沿用这个编号。一个编号只对应一个页面，同一页面可以支撑多个有明确边界的细节。这不是新的格式门槛：完整 URL 写法继续可用，不要求新增 JSON、文件或固定版式。

只把正文实际采用的已审计页面关联到来源表；候选或仅访问过的入口继续在 06 保留。来源编号、实际 URL、来源名称要相互一致，不能把视频编号代替视频 URL，不能把 Gitee 描述配到 GitHub 链接。合并重复具体页面来源行时保留全部引用编号和不同支撑内容。同一搜索 URL 的不同审计记录不能合并；已有明确审计 ID 的来源保留其绑定，07 的 URL 编号不能覆盖该次访问。

不要复制上游明显影响理解的错字或坏句，也不要把各章不同的产品机制、用户任务、竞品限制、渠道条件压成同一句结论；先按上下文和已有材料修正。纯写作风格不同不是重新调研或阻止交付的理由。


## 长材料读取与来源身份

主代理、吸收与复核均按累计读取完整文件处理 07/08：长文件分页至 EOF，小文件也可整读，不以一次 Read 的参数形式判定完成。读取失败或材料已改写时，不复用旧版本读取记录。

长文章、视频和搜索 URL 不要凭标题或平台名重新拼接，也不要删除参数。07 可保留 [S1]: audit:<exact-audit-id>，与事实旁的 [S1] 配套；主代理沿用，服务端按同一次真实成功审计恢复完整页面 URL。没有审计 ID 时复制完整已审计 URL。一个编号对应一个页面/访问记录，多页面用多个编号；缺少这种可选编号不阻止交付，不新增 JSON 或字段配额。

未取得、不得冒充、未来建议不等于已观察事实；空补写清单和可选建议不构成必须补丁。只有具体的来源支持错误或遗漏才要求修正。


## 收尾整理：复用复核结果，不把未采用写成未取得

E 先完整读取 brief 与 05，再按需回查 06 或已登记分片的具体段落；D 已完成全分片复核，不要求 E 再整读所有原始材料。先保存实质章节材料与来源；只用 Read/Write，Write 覆盖保存时带齐累计正文，不把空提纲或压缩摘要当成已完成。

区分“已取得并采用、已取得但未采用、部分取得、未取得、访问受限”：未列入来源表不等于未取得。视频简介可读而评论未取得，是部分证据，不是整个平台受限。按具体页面和本次访问核对，不得用另一条失败记录覆盖成功内容。

每个实际用于正文的具体页面保留完整 URL 或真实 audit ID，推荐一页一编号并在正文与来源表沿用；多条评论、博文不得只留一个代表链接，搜索结果不得换成网站首页。普通 Markdown 引用定义、行内链接与带明确编号的来源表都可用，不新增格式或来源数量门槛。

公开标价或免费边界只能证明竞品采用了该方案，不能证明转化、盈利或付费意愿已经验证；一家竞品免费商用不能证明整个品类无法靠商用授权收费。有依据的 AI 推断继续保留，但要写依据、成立条件与可推翻条件，不能伪装为已验证定论。

08 在现有复核中检查上述三点，只提出已有证据支持的最小章节/来源补丁，不新增调研、代理、复核轮次或生成门槛。
