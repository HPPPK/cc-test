## UIUX generated-image-only applicability
This is the executable image-native adaptation. Audited upstream originals and licenses are archived under third_party and are not runtime instructions.

# Screenshot-driven redesign
先读用户消息中的 inline image 图像块；只有文件路径时先 Read。文件名不是像素证据。页面类型保持通用，购买只是一个例子。
## 现状 → 任务 → 改动
- 记录实际可见的阅读顺序、主次区域、文字、色彩、操作入口、选中状态和屏幕边界。给每条观察指明位置。
- 分离截图事实、用户已确认事实、参考观察、设计假设、未知项。静态图片不能证明用户喜好、转化率、隐藏状态、键盘行为。
- 按阻碍核心任务的程度列 P0/P1/P2：位置 → 影响的任务 → 原因假设 → 具体空间调整 → 如何用终图核对。不要只写“提高高级感”。
- 保留原页面的语境和密度。工具内弹窗不要默认扩成营销落地页，不添加无来源的导航、仪表盘、评价或服务承诺。
- 不因美化而擅自删套餐、改价格或推断授权。不可读细字标为未知。
## 方向
先完成灵感范围和获准研究，再提出 2–3 个信息组织不同的方向；说明阅读路径、主角、字体职责、密度、边界关系、风险。不是同稿换色。
已有明确方向或用户代选授权就复用；否则 AskUserQuestion id=design_direction。用户后来追加材料不应自行解释为新的收费任务。
## 输出
把选定构图和不可变事实交给 uiux-image-art-direction；最终交付来自 image_generation 并 Read 的图片。诊断不等于已经生成或通过视觉复审。
