# UI craft critique
从真实读到的最新图片作设计批评，不凭方法名称批准。
## 三层判断
1. 目的：第一眼是谁在这里做什么？主任务、对象、后续动作是否连得起来？
2. 组织：信息主次、相邻关系、阅读轴、空白密度、重复、分组和文案是否支持目的？
3. 工艺：字体角色、断行、对齐、图标含义、边缘、色彩和状态是否一致？
## Findings 格式
位置与可见证据 → 影响的用户任务 → 严重度 → 针对性修正 → 保留项。Critical 是误导事实/遮挡主任务；High 是明显损害层级或可读性；Polish 是局部精修。不要把个人喜好伪装成 Critical。
先说明一到两个具体有效设计，再按影响排序指出问题。禁止“更精致、更高级、优化体验”这类没有位置和动作的评语。至少两条不同观察进入最终收据。
批评不触发无限制作循环：按总流程最多一轮有依据修订；剩余问题用 NEEDS_WORK 交代。
